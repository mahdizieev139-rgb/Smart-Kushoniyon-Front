# ТЕХНИЧЕСКОЕ ЗАДАНИЕ (ТЗ) — KUSHONIYON SMART MARKET

**Frontend Development — Version 1.0**

> Этот документ описывает frontend-приложение (Next.js), которое подключается к
> отдельному backend REST API (репозиторий `Smart-Kushoniyon-Back`) по адресу
> `/api/v1`. Backend ТЗ — см. `docs/backend-tz.md`.

---

## 1. Общая информация

- **Название проекта:** KUSHONIYON SMART MARKET
- **Тип продукта:** Digital Marketplace Platform / B2B SaaS (клиентская часть)
- **Локация:** рынок Кушониён, Душанбе, Таджикистан
- **Целевая аудитория:** покупатели, продавцы (владельцы торговых точек), администрация рынка.

**Цель:** удобный, быстрый, многоязычный веб-интерфейс, который показывает магазины,
товары, цены и карту рынка покупателям, и даёт продавцам и администраторам панели
управления. Frontend — отдельное приложение, общается с backend только через REST API.

---

## 2. Технологические требования

**Обязательный стек:** Next.js (App Router), React, TypeScript, Tailwind CSS,
TanStack Query, Zustand, React Hook Form, Zod, next-intl, MapLibre GL JS, PWA.

- **Рендеринг:** App Router, серверные и клиентские компоненты
- **Состояние сервера:** TanStack Query (кэш, загрузка, повтор)
- **Состояние UI/аутентификации:** Zustand (access-токен только в памяти)
- **Формы:** React Hook Form + Zod
- **Интернационализация:** next-intl, маршруты с префиксом локали

---

## 3. Роли и доступ (на стороне клиента)

Интерфейс адаптируется под роль; реальную проверку всегда выполняет backend.

| Роль | Доступ |
|------|--------|
| **CUSTOMER / гость** | Публичные страницы: магазины, товары, карта, поиск |
| **SELLER** | + Панель продавца: свои магазины и товары |
| **ADMIN / SUPER_ADMIN** | + Панель администратора: модерация, аналитика |

Маршруты `/seller/*` и `/admin/*` защищены клиентским guard'ом (`RequireAuth`):
пока сессия восстанавливается — спиннер; нет сессии — редирект на `/login`;
неверная роль — сообщение «нет доступа».

---

## 4. Интернационализация (обязательно)

- Три языка: **таджикский (tj, по умолчанию)**, русский (ru), английский (en).
- Все URL с префиксом локали: `/tj/...`, `/ru/...`, `/en/...`.
- Весь текст интерфейса — в словарях `src/messages/{tj,ru,en}.json`; **ничего не
  захардкожено** в компонентах.
- Переключатель языка остаётся на той же странице и меняет только префикс.
- Контент (магазины, товары, категории) приходит с backend уже на нужном языке
  (параметр `?locale=`).

---

## 5. Дизайн-система

- **Палитра:** Navy `#163A63`, Blue `#2878D0`, фон `#F4F6F9`, белый `#FFFFFF`,
  акцент (construction amber) `#E8A33D` — умеренно.
- **Шрифты:** Manrope (заголовки), IBM Plex Sans (текст, кириллица),
  IBM Plex Mono (цены, табличные цифры).
- **Требования:** адаптивность (mobile-first), доступность (видимый фокус,
  `prefers-reduced-motion`), состояния загрузки/пустоты/ошибки, уведомления,
  подтверждения, единые токены (цвет, радиус, тени).
- **Фирменный элемент:** «locator chip» (Ворота · Ряд) — навигационная метка,
  связывающая листинг с реальным расположением на рынке.

---

## 6. Публичные страницы

1. **Главная:** шапка, логотип, переключатель языка, строка поиска, категории
   (живые данные), избранные магазины, популярные товары, блок карты, блок «стать
   продавцом», тарифы (Basic 1 500 / Extended 2 500 TJS — предложение), подвал.
2. **Магазины:** список одобренных магазинов, поиск, пагинация, карточки.
3. **Магазин (детали):** название, описание, телефон, расположение (locator chip),
   каталог товаров магазина.
4. **Товары:** сетка, поиск, фильтр по категории, фильтр по цене (min/max),
   сортировка (новизна / цена ↑ / цена ↓), пагинация.
5. **Товар (детали):** галерея, название, описание, цена, валюта, наличие, продавец,
   контакт.
6. **Вход / Регистрация:** формы с валидацией; регистрация как Покупатель/Продавец.

---

## 7. Интерактивная карта рынка (ключевая функция)

- Технология: **MapLibre GL JS** (бесплатные тайлы OpenStreetMap, без ключа).
- **Два режима** (переключатель):
  - **«План»** (по умолчанию): самодостаточная схема-план рынка (ворота → ряды →
    магазины-«стойла»), рендерится всегда, без тайлов и координат.
  - **«Карта»**: географическая карта с маркером для каждой секции, у которой есть
    координаты.
- Поиск магазина на карте/плане.
- **Нельзя выдумывать реальные координаты рынка.** Демо-данные помечены DEMO;
  реальные координаты добавляются после обследования рынка (см. `docs/demo-map-data.sql`).
- Готовность к будущим indoor-картам / план-схемам.

---

## 8. Панель продавца

- Обзор: статистика своих магазинов и товаров (всего / одобрено / на модерации).
- Мои магазины: список + создание магазина (название/описание на 3 языках, телефон).
- Мои товары: список + добавление / редактирование / удаление; поля — название и
  описание на 3 языках, цена, валюта (TJS), категория, наличие, загрузка изображений.
- Статусы товара/магазина отображаются бейджами.

---

## 9. Панель администратора

- Обзор: общая аналитика (магазины, товары, продавцы, на модерации, реклама, подписки).
- Магазины: фильтр по статусу, действия **одобрить / отклонить / заблокировать**.
- Товары: фильтр по статусу, действия **одобрить / отклонить**.
- Все действия вызывают backend и обновляют списки/счётчики.

---

## 10. Интеграция с API

- Единый клиент (`src/lib/api-client.ts`): базовый URL из `NEXT_PUBLIC_API_URL`,
  заголовок `Authorization: Bearer <access>`, `credentials: 'include'`.
- **Молчаливое обновление токена** при 401 (один раз) через refresh-cookie.
- Единый формат ответа: `{ success, message, data, meta? }`.
- Access-токен хранится только в памяти (не в localStorage) — защита от XSS.

---

## 11. PWA

- Web-манифест, иконка, service worker, offline-страница.
- Статика кэшируется; **API, auth и страницы seller/admin НЕ кэшируются**
  (приватные данные не попадают в общий кэш).
- Service worker регистрируется только в production.

---

## 12. Нефункциональные требования

- **Производительность:** пагинация, кэш запросов, ленивая загрузка карты/воркера.
- **Безопасность (клиент):** токен в памяти, guard маршрутов (UX), доверие только
  backend'у для реальных проверок, никаких секретов в коде.
- **Надёжность:** состояния загрузки/ошибки/пустоты на каждом экране; graceful
  деградация (например, карта-план работает офлайн).
- **Доступность:** клавиатурный фокус, aria-метки, уважение reduced-motion.

---

## 15. Критерии приёмки

Frontend готов, если: (1) dev-сервер и build запускаются без ошибок;
(2) все три языка работают; (3) публичные страницы отображают реальные данные с
backend; (4) поиск, фильтры, сортировка, пагинация работают; (5) карта (план и
географическая) отображается; (6) вход/регистрация работают; (7) панели продавца и
админа защищены по ролям и выполняют свои операции; (8) PWA устанавливается и имеет
offline-страницу; (9) нет ошибок TypeScript; (10) production build проходит;
(11) приложение подключается к API.

## 16. Порядок разработки

1. Инициализация (Next.js, Tailwind, i18n, дизайн-система, API-клиент, auth-store)
2. Публичный сайт (главная, магазины, товары, детали, поиск)
3. Интерактивная карта (MapLibre + план)
4. Панели продавца и администратора (RBAC)
5. PWA, тесты, документация, production build

---

## 17. Результат

Полноценное, многоязычное, адаптивное frontend-приложение KUSHONIYON SMART MARKET,
готовое к подключению к backend и к демонстрации администрации рынка Кушониён.
Автоматический деплой не выполняется: GitHub, хостинг, домен и сервер настраивает
владелец проекта самостоятельно.
